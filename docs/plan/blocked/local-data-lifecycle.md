## Remaining Blocker

Define owner-specific atomic preview/inventory and quiescence guarantees before
source removal/redaction. Runtime deletion cascades descendants without a discovered
revision-bound preview; sidecar per-session artifact ownership is not enumerable
from the index alone. Cross-store partial-failure/retry semantics remain unresolved.
Do not write direct SQLite mutations or broad directory removal to work around this.
The installed OpenCode 2.2.5 API was checked in a disposable standalone instance:
parent-filtered pagination is available, but delete takes only a session ID and
the activity list covers only foreground drains in that process. These do not bind
a descendant set to deletion or exclude all writers.

`docs/specs/local-data-lifecycle-coordination.md` proposes an owner-bound
admission, durable dispatch, outcome, retry, and recovery contract with a
fault-injection matrix. It is design only: neither the coordinator nor the
required owner capabilities are implemented, and this task remains blocked.

The offline sidecar planner also accepts safely representable fallback IDs
generated by the index owner. This only improves the suggested inspection step;
it does not verify identity, uniqueness, affected artifacts, or authorization.
The owner `show`, `current`, and `handoff` commands reject duplicate selected
IDs in their parsed snapshot; this does not bind future changes or establish a
cross-artifact inventory.
The owner index writer also refuses any duplicate parsed IDs before pruning or
publishing the index. A surrounding digest run may already have changed other
artifacts, so this is not a cross-sidecar transaction.
